# 저자 귀속을 포기하고 대화 내 관측만 저장한다

어떤 훅도 "이 코드를 학생이 직접 썼는지"를 알려주지 않는다. 에이전트의 쓰기는
`PostToolUse`로 완전히 관측되지만, 학생이 자기 에디터에서 짠 코드는 어떤 툴 훅도
울리지 않는다. 문서가 지원하는 유일한 귀속 경로는 에이전트 write 원장과 `git diff`의
뺄셈인데, 커밋 습관·리베이스·포매터·외부 AI 사용에서 **조용히** 틀린다.
틀린 프로필은 회복 불가능하고 불완전한 프로필은 회복 가능하므로, 귀속을 포기하고
대화에서 관측 가능한 것만 기록한다. 그래서 저장 단위는 해석이 아니라 행동이다 —
"혼자 구현해냄"이 아니라 "구현을 제안했고 3턴간 질문 없이 진행함".

## Considered Options

- **git 뺄셈** — 유일하게 문서가 지원하는 귀속 경로. 조용히 틀리므로 기각.
- **명시적 확인** ("이거 혼자 하신 거 맞죠?") — 정확하지만 귀찮고, 부트캠프 맥락에서는 거짓말 유인이 있다.
- **대화 내 증거만 + 귀속 포기** — 채택.

## Consequences

- `kind` 열거형이 행동 동사만 갖도록 강제된다. `understood`/`weak_at` 같은 판정은 스키마에 들어올 수 없다.
- 관측이 오래돼도 여전히 참이다. "질문했다"는 6개월 뒤에도 사실이지만 "이해가 부족하다"는 아니다.
- **`c`(숙련도) 추정이 한쪽으로 편향된다.** 대화 밖 작업이 보이지 않으므로 조용히 잘하는
  학생일수록 관측이 적고, 시스템은 그를 초보로 보아 개입을 과하게 건다. 랜덤 오차가 아니라
  항상 낮게 추정하는 계통 오차다.
- **구현→검수 분리가 학생의 직접 작업을 관측 가능하게 만드는 유일한 개입 형태가 된다** —
  학생이 결과를 들고 와야 루프가 닫히기 때문이다. 개입 형태 설계가 이 결정에 종속되어 있다.
- 나중에 귀속을 도입하더라도 이미 쌓인 관측에는 소급되지 않는다.
