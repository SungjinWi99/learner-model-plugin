# 설계

용어는 [CONTEXT.md](../CONTEXT.md)를 따른다. 이 문서는 그 어휘로 쓴 구현 설계다.
되돌리기 비싼 결정 두 개는 [ADR](adr/)로 따로 기록했다.

## 1. 문제

코딩 에이전트는 작업 완료를 위해 만들어졌고, 학생의 역량 강화를 위해 만들어지지 않았다.
막연한 요구만으로도 전부 해결해주기 때문에 학생이 고민하고 트러블슈팅하며 성장할 기회가 없다.

목표는 코딩 에이전트 위에 한 겹을 얹어, **학생의 개발 경험을 영속적으로 기억하고**
그 기억에 근거해 **작업마다 에이전트의 개입 형태를 조절**하는 것이다.

### 선행 시도에서 배운 것

같은 아이디어의 간소화 버전(sabu 플러그인)을 실제로 사용했고, 두 가지가 관찰됐다.

1. **프로필이 17일간 갱신되지 않았다.** 원인은 기록 실패가 아니라 이탈이었다 —
   해커톤 기간에 학습보다 속도가 중요해지자 다른 에이전트로 옮겨갔다.
2. sabu에는 "지금 느려질 여유가 없다"를 표현할 수단이 없었다. 강도 설정(lite/full/spartan)은
   숙련도의 대용품이지 여유가 아니다. 그래서 사용자가 쓸 수 있는 유일한 표현이 도구를 끄는 것이었다.

→ **여유(slack)를 1급 축으로 두지 않으면, 학생은 바쁠 때마다 이탈하고 그 기간의 관측이 통째로 유실된다.
그런데 바쁜 기간이 개발을 가장 많이 하는 기간이다.**

## 2. 배치 맥락

- 부트캠프 코호트 단위 배포. 트랙은 AI / 풀스택 / 클라우드 셋이고 학생은 하나를 수강한다.
- 커리큘럼 문서는 존재하지만 사용할 수 없다. 역량 뼈대를 커리큘럼에서 가져올 수 없다.
- 지원 호스트는 Claude Code와 Codex CLI. 대부분의 학생은 둘 중 하나만 쓴다.
- 학습자 프로필은 **강사에게 가지 않는다.** 학생이 검토·편집·승인한 사본만 플러그인 개발자에게 간다.

## 3. 호스트 제약 (조사로 확인된 사실)

| 항목 | Claude Code | Codex CLI 0.149 |
|---|---|---|
| `UserPromptSubmit` 컨텍스트 주입 | `additionalContext` / plain stdout | 동일 |
| `UserPromptSubmit` 타임아웃 | **30초** (다른 이벤트는 600초) | 600초 |
| 주입 크기 | **10,000자 하드캡** | ~2,500토큰 소프트, 초과 시 파일로 흘리고 프리뷰 |
| stdin 필드 | `session_id` `prompt` `cwd` `transcript_path` | 동일 (이름 변환 불필요) |
| 파일 쓰기 관측 | `PostToolUse` `tool_name: Write\|Edit` | `apply_patch`, 셸 경유는 `Bash` — **둘 다 봐야 함** |
| 영속 데이터 디렉터리 | `${CLAUDE_PLUGIN_DATA}` | `PLUGIN_DATA` + `CLAUDE_PLUGIN_DATA` 별칭 |
| 배포 | 마켓플레이스(git repo) + `/plugin` | 마켓플레이스(git repo) + `codex plugin add` |
| 훅 실행 전 신뢰 승인 | 불필요 | **필수** (`/hooks`에서 사용자가 직접) |
| `SessionEnd` | 1.5초 예산 공유 — 실질적으로 쓸 수 없음 | 1초 |

구속 조건은 **Claude의 30초 / 10,000자**다. 양쪽에서 이 이하로 설계한다.
Cursor는 per-prompt 컨텍스트 주입이 불가능하므로 지원 대상이 아니다.

## 4. 저장소

**고정 공통 경로 `~/.devprofile/`.** 호스트가 제공하는 `PLUGIN_DATA`를 쓰지 않는다 —
두 호스트가 서로 다른 물리 경로로 해석하면 프로필이 둘로 갈라지고,
학습 기록에서 진실 원천이 둘인 것은 치명적이다. 홈 아래 고정이므로 프로젝트를 옮겨도 하나로 유지된다.
역량은 프로젝트가 아니라 사람에 붙는다.

```
~/.devprofile/
├── raw/2026-08-23.jsonl     계층 1: 훅이 무판단 append
├── obs.jsonl                계층 2: 관측 (프로필의 실체)
├── archive/obs-*.jsonl      접힌 관측 (v1에서는 생성 안 함)
├── tags.json                역량 태그 목록 (pending / active)
└── profile.json             트랙, 목표, 익명 ID
```

## 5. 관측 파이프라인

### 계층 1 — raw 이벤트

훅이 이벤트마다 한 줄 append한다. **LLM 호출 없음, 판단 없음.** 실패할 여지가 없다.

```jsonl
{"t":"14:02:11","e":"prompt","sid":"a1","cwd":"~/proj/rag","text":"검증 노드 추가해줘"}
{"t":"14:02:12","e":"inject","sid":"a1","comp":["langgraph/send"],"form":"design_split"}
{"t":"14:03:40","e":"turn_end","sid":"a1","tail":"...Send()로 팬아웃하는 부분은..."}
{"t":"14:11:20","e":"write","sid":"a1","tool":"Edit","path":"src/graph/verify.py","d":+12}
{"t":"14:15:10","e":"prompt","sid":"a1","text":"아 그냥 해줘","override":true}
```

- `d`는 변경 줄 수만. **코드 본문은 저장하지 않는다.**
- `override`는 짧은 문구 목록으로 훅이 감지한다.
- `prompt.text`는 원문이 들어간다 → **정제 후 7일 뒤 폐기.**

### 계층 2 — 관측

```jsonl
{"id":"o_8f21","t0":"2026-08-23T14:02Z","t1":"14:15Z",
 "comp":["langgraph/send","python/async"],
 "kind":["asked","overrode"],
 "text":"병렬 팬아웃에 Send()가 필요하다는 안내를 받은 뒤 리스트 반환과 무엇이 다른지 되물었고, 에이전트가 12줄을 반영한 4분 뒤 우회를 요청함",
 "status":"closed","src":["a1@14:02..14:15"]}
```

**단위는 턴이 아니라 에피소드다.** 하나의 역량에 대한 한 차례 시도가 시작부터 끝까지 1 관측.
턴 단위로 쪼개면 13분 대화에서 3개가 나오지만(12주에 2,400개), 에피소드 단위면 1개다(12주에 300~600개).

- `kind`는 **순서 있는 배열**이다. `["asked","implemented","overrode"]`와 `["implemented","asked"]`는 다른 이야기다.
- `kind` 값은 **전부 행동 동사**다: `proposed` `asked` `implemented` `debugged` `stuck`
  `overrode` `deferred` `corrected` `observed`.
  `understood`나 `weak_at` 같은 **판정은 값이 될 수 없다** — 그건 해석이다.
- `src`로 raw까지 되짚을 수 있다. 관측이 이상하면 근거를 열어봐야 하고, 추출 품질 분석의 유일한 재료다.
- **관측은 희소하다.** 대부분의 턴은 0개를 낸다. 에이전트가 시킨 일을 한 것뿐인 턴은 관측이 아니다.

### 추출

2단 자기치유 구조다.

| 시점 | 하는 일 |
|---|---|
| `Stop` 훅 (매 턴) | 이번 세션의 `open` 관측 목록과 방금 턴의 raw를 보고 **연장 또는 신규 생성**(upsert) |
| `SessionStart` (다음 세션) | `extracted` 표시가 없는 밀린 raw를 몰아서 처리 |

`Stop`이 실패해도 아무것도 잃지 않는다. raw는 이미 디스크에 있고 표시가 없으니 다음 세션이 주워간다.
**"조용히 기록되지 않음"이 구조적으로 불가능해진다.**

에피소드는 다음 세 조건 중 하나라도 만족하면 닫힌다: 세션 종료 / 역량 태그가 바뀜 / 마지막 활동 후 N분 무응답.

추출은 **동기**로 구현한다. 비동기는 실패가 조용해지고, 지금은 실패를 시끄럽게 만드는 편이 낫다.

## 6. 역량 모델

**고정 뼈대는 직교축 4개뿐이다:** `디버깅` `테스트` `설계` `도구·환경`.
커리큘럼 문서를 쓸 수 없으므로 도메인 뼈대는 만들지 않는다.
**추정한 뼈대가 틀리면 오분류가 조용히 쌓인다 — 없는 뼈대보다 틀린 뼈대가 나쁘다.**

나머지 잎사귀는 관측에서 자란다(`langgraph/send` 등). 파편화·폭발을 막는 장치 셋:

1. **기존 태그 목록을 추출 프롬프트에 항상 넣는다.** "여기서 고르고, 정말 없을 때만 새로." 파편화의 대부분이 여기서 막힌다.
2. **새 태그는 `pending`으로 만들고, 2회 이상 나와야 승격한다.** 한 번 해본 것은 역량이 아니다.
3. **깊이는 `<도메인>/<구체>` 2단으로 고정한다.**

**트랙은 taxonomy 노드가 아니라 학생 속성(태그)이다.** 분석에서 트랙별로 갈라 봐야 한다.

## 7. 검색

훅에서 **결정론적으로** 돈다. 점수 함수도, 감쇠 상수도, 반감기도 없다.

```
1. 작업의 역량 태그를 얻는다        ← 여기만 LLM
2. obs.jsonl에서 그 태그로 필터      ← 코드
3. 최신순 정렬                     ← 코드
4. 상위 8개                        ← 코드
```

역량당 관측이 수십 개 규모라 정교한 랭킹이 필요 없다.
노후화는 별도 로직으로 처리하지 않는다 — **관측에 시점이 있으니 판단하는 쪽이 보고 할인한다.**
감쇠 상수를 코드에 박으면 틀렸을 때 조용히 계속 틀리지만,
에이전트가 날짜를 보고 판단하면 개입 사유에 드러나고 학생이 반박한다.

주입량은 5~15개, 1,000~2,000자. **프로필이 300개든 2,400개든 주입량은 일정하다.**

## 8. 개입 결정

### 세 축

- **숙련도** — 이 역량에서 도움 없이 끝낼 수 있는 정도. 관측에서 추론한다.
- **학습가치** — `ZPD(숙련도) × 관련성`. 숙련도가 바닥일 때 **낮고**(발판 없이 굴리면 좌절만 한다),
  천장일 때 0이며, 그 사이에서 최대다.
- **여유** — 시스템이 추론하지 않는다. 학생의 행동에서만 온다.

단일 스칼라로는 불가능하다. 숙련도가 오를 때 에이전트의 일은 `많음 → 줄어듦 → 다시 많음`으로 비단조다.
**뉴비의 시범과 마스터의 침묵 대행은 분담이 같고 산출물이 다르다** — 하나의 축으로는 구분되지 않고, (숙련도, 학습가치) 쌍으로는 자명하다.

### 결정 절차

```
1. 사소함 게이트 : 배울 게 있나? 없음 → 침묵 대행, 사유 표시 없음, 끝.
2. 여유 확인     : 여유 없음 → 침묵 대행, 끝. (단 관측은 계속 쌓는다 → 미룬 레슨)
3. 레슨 초점     : 역량 태그 중 학습가치 최대인 것 하나.
                  최근 개입한 역량은 감점(기아 방지).
4. 형태 선택     : 초점 역량의 숙련도로 아래 표에서 하나.
5. 사유 1줄      : 관측 하나만 인용.
```

**숙련도는 훅이 코드로 센다. LLM을 부르지 않는다.** 초점 역량의 최근 관측에서 `kind` 값의
분포를 세면 된다 — 최근 것들이 질문 없이 `implemented`뿐이면 높음, `stuck`/`overrode`가 섞이면 중간,
`stuck` 위주면 낮음, 관측이 없으면 기본값. `kind`를 행동 동사 열거형으로 정한 이유가 여기 있다.

훅의 숙련도는 정교할 필요가 없다. **빠르고 일관되기만 하면 된다.** 미묘한 판단은 그 다음,
에이전트가 코드를 보면서 하는 곳에서 일어나고, 거기서는 개입 사유로 드러나 학생이 반박할 수 있다.

**개입은 역량이 아니라 작업 전체에 건다. 역량은 개입의 대상이 아니라 근거다.**
`langgraph/send`와 `python/async`는 같은 세 줄이라 나눌 수 없다.
레슨 초점은 형태를 *어디에 겨눌지*만 정한다 — 골격이면 어디에 빈칸을 뚫을지, 설계 분리면 무엇을 물을지.
관측은 여러 역량에 걸리고(`comp`는 배열), 개입은 하나다.

초점이 아닌 역량을 에이전트가 처리할 때는 **한 줄 설명을 남기고 `observed` 관측으로 기록한다.**
학습은 아니지만 노출은 되고, 나중에 그 역량이 초점이 됐을 때 근거가 된다 —
"지난번에 제가 쓴 테스트 보셨죠, 이번엔 직접."
이것이 `observed`의 유일한 생산 경로다.

### 다섯 형태

| 형태 | 학생 | 에이전트 | 조건 | 나오는 관측 |
|---|---|---|---|---|
| **침묵 대행** | — | 전부, 설명 없음 | 게이트 미통과 / 숙련도 천장 / 여유 없음 | 없음 |
| **시범** | 읽고 질문 | 전부 + 설명 | 숙련도 바닥 | 희박 |
| **골격** | 빈칸 3~10줄 | 나머지 구조 전부 | 숙련도 낮음 | 잘 나옴 |
| **설계→구현 분리** | 문제정의·설계 | 구현 전부 | 숙련도 중간 — **기본값** | `proposed` / `stuck` |
| **구현→검수 분리** | 정의·설계·구현 | 검토·지적 | 숙련도 높음 | `implemented` + 검토 대화 |

선형 사다리가 아니다. 골격은 구현 능력을, 설계 분리는 설계 능력을 잰다.
초보에게는 추상(설계 발화)이 구체(빈칸 채우기)보다 어려울 수 있다.

**골격**: 구조는 다 쓰고 레슨인 3~10줄만 비운다. 빈칸은 한 개념당 하나.
주석에 무엇을 채워야 하는지와 참고 위치만 쓰고 답은 쓰지 않는다.
훈련 버그보다 안전하다 — 빈칸은 안 채우면 즉시 안 돌지만, 틀린 코드는 조용히 돌다 나중에 터진다.

**설계→구현 분리**: 코드를 쓰기 전에 묻는다. "먼저 어떤 단계가 필요할 것 같으세요? 대충이라도 좋아요."
답이 오면 **그 설계 그대로** 구현한다. 구멍이 있어도 조용히 고치지 않는다.

**구현→검수 분리**: 코드를 한 줄도 쓰지 않는다. 건드릴 위치까지만 알려주고 기다린다.
학생이 "했어요"라고 하면 읽고 검토한다. **학생이 직접 짠 코드를 관측 가능하게 만드는 유일한 형태다** —
결과를 들고 와야 루프가 닫히기 때문이다.

### 강등

```
설계→구현 분리 ──[설계 질문 1회 실패]──▶ 골격 ──[빈칸도 못 채움]──▶ 시범
```

**질문은 1회다.** 관측이 없는 초기에 3번 캐묻는 것은 심문이다. 못 답한 것 자체가 `stuck` 관측이다.
강등은 조용히 한다 — "그럼 구조는 제가 잡아둘 테니 핵심만 채워보시죠". 실패를 지적하지 않는다.

**승격은 작업 중에 하지 않는다.** 다음 작업의 숙련도 추정이 올라갈 때 자연히 올라간다.
그 자리에서 난이도를 올리면 잘할수록 벌받는 구조가 된다.

### 여유와 우회

우회(`그냥 해줘`)는 **여유를 알리는 유일한 입력이자 개입 오판을 세는 유일한 계측 지점**이다.
1회성 + "이번 세션 내내" 선택지 + **연속 3회 우회 시 자동으로 여유 낮음 전환**.
자동 전환된 사실 자체가 강한 관측이다.

> ⚠️ 지표를 셀 때는 `우회 + 자동침묵전환` 합계로 센다. 우회 횟수만 세면
> 시스템이 조용해질수록 지표가 좋아지는 — 아무것도 안 할수록 잘하는 걸로 보이는 — 함정에 빠진다.

### 미룬 레슨

여유가 없어 침묵 대행으로 넘어갔지만 학습가치가 높았던 작업은 `deferred`로 남는다.
바쁜 기간이 학습의 공백이 아니라 **학습 백로그**가 된다.

> "지난 2주 동안 이런 걸 하셨네요. 그중 3개는 원리를 안 보고 지나갔습니다. 지금 볼래요?"

### 개입 사유

선택한 형태와 함께 한 줄 근거를 표시한다. **관측 하나만 인용**하고, 같은 근거를 세 번 이상 반복하지 않는다.

```
[설계→구현 분리] 지난주에 StateGraph를 직접 구성하셨으니, 이번엔 분해까지 해보시죠.
                 (그냥 해줘 → 우회)
```

목적은 설득이 아니라 **노출**이다. 근거가 틀리면 학생이 즉시 안다 — "그거 제가 한 거 아닌데요".
학생이 뭘 우회하는지 알아야 우회할 수 있으므로, 표시는 필수다.

### 에이전트에게 전달하는 방식

훅이 매 프롬프트에 **관측 + 권장 형태 + 형태별 행동 규칙 요약**을 함께 주입한다.
에이전트는 근거가 있으면 뒤집을 수 있고, 뒤집힌 횟수도 계측된다.

규칙을 세션 시작 1회만 주입하면 긴 세션에서 희석되고,
스킬로 두면 에이전트가 로드하기로 *결정*해야 하는데 그 결정 지점이 곧 드리프트 지점이다.
매 프롬프트 주입이 이미 존재하므로 규칙을 얹는 한계 비용은 사실상 0이다.

## 9. 첫 세션

관측이 0이므로 물을 것만 묻는다: **트랙과 목표.** 자가평가는 받지 않는다 —
sabu 프로필의 Skill Map 세 항목이 전부 자가평가였고, 그 뒤로 한 번도 실제 관측으로 갱신되지 않았다.
**자가평가를 씨앗으로 심으면 영원히 남는다.**

기본 개입은 **설계→구현 분리**. 기본값의 조건은 "가장 높은 단"이 아니라 **"관측을 낳는 가장 낮은 단"**이다.
설계 발화는 대화 안에 있으니 관측 가능하고, 실패가 30초 만에 드러나 그 자리에서 강등된다.
구현→검수 분리를 기본값으로 잡으면 못 하는 학생이 30분을 헤매고 나서야 실패를 알게 된다 — 이탈의 가장 흔한 원인이다.

## 10. 제출

학생이 명령하면 제출본을 렌더해 보여주고, 지우고 싶은 항목을 지운 뒤 최종 확인하면 전송한다.
**학생의 명시적 승인 없이는 발생하지 않는다.** 강사는 받지 않는다.

- 전송: **클립보드 복사 + 구글폼 URL 열기.** 학생이 붙여넣고 제출한다.
  prefilled URL은 길이 제한에 걸려 조용히 잘리고, 직접 POST는 폼 구조가 바뀌면 조용히 깨진다.
  **붙여넣기의 마찰이 동의를 진짜로 만든다.**
- 식별: **랜덤 익명 ID + 트랙 태그.** 이름은 필요 없다. 익명이면 학생이 덜 지우므로 데이터 품질이 올라간다.
- 지운 항목은 **사본에서만 빠진다.** 원본 프로필은 그대로다.
  → ⏸ **보류:** 프로필이 틀렸을 때 학생이 원본을 고칠 통로를 따로 둘지는 아직 결정하지 않았다.
  당장은 개입 사유 노출(§8)이 그 역할을 부분적으로 대신한다.

받은 데이터로 볼 것은 우선순위대로: **(1) 채택/이탈** — 관측의 타임스탬프 분포에서 끊긴 지점이 곧 이탈 지점이고
직전 관측이 원인 후보다. **(2) 개입 오판** — 우회가 언제 일어났나. **(3) 역량 매핑 품질**.

## 11. 배포

git repo 하나가 양쪽 마켓플레이스 역할을 한다.

설치 경로는 **학생이 자기 코딩 에이전트에게 repo 주소를 주고 설치를 맡기는 것**이다. 성립 조건:

- `README.md`는 사람용 산문으로 두고, **에이전트용 절차서 경로를 상단에 한 줄로 안내**한다.
- 절차서는 호스트 감지 → 분기 → 명령 시퀀스 → **자체 검증** 순서로 쓴다.
- 검증은 더미 프롬프트를 한 번 돌려 훅이 실제로 주입했는지 확인한다.

> ⚠️ **Codex의 훅 신뢰 승인은 에이전트가 대신할 수 없다.** `/hooks`는 사용자 대화형 승인이다.
> 여기가 유일하게 남는 수동 단계이자 **유일한 조용한 실패 지점**이다 —
> 승인하지 않으면 플러그인이 설치돼도 아무것도 하지 않는다. 자체 검증이 이것을 잡아야 한다.
>
> 이 구분이 중요한 이유: 자체 검증이 없으면 **"안 쓴 학생"과 "못 쓴 학생"을 구분할 수 없다.**
> 둘은 완전히 다른 문제고 처방도 정반대다.

## 12. v1 범위

관측 파이프라인과 개입 조절을 모두 넣는다. **구현 순서는 파이프라인 먼저, 개입을 그 위에** —
그래야 개입이 빈 프로필 위에서 도는 상태를 만들지 않는다.

성공 지표는 **(1) `우회 + 자동침묵전환` 합계**, **(2) 프로필 생존율**(6주 뒤에도 갱신되고 있고 실제 실력과 일치하는가).
학습 성과 자체는 측정하지 않는다 — 침입적이고, 이탈이 먼저 죽인다.

### v1에서 만들지 않는 것

- **압축/접기.** 12주 코호트에서는 300~600개면 다 들고 가도 된다. 필요해지면 역량당 상한(개수 기준)으로 넣는다.
- **임베딩 검색.** 태그 필터 + 최신순으로 시작한다. 수백 개 규모에서는 grep이 즉시 끝난다.
- **sqlite.** JSONL로 시작하고, 수천 개를 넘으면 옮긴다. 이전은 쉽다.
- **훈련 버그.** 골격이 더 안전한 사촌이다. 디버깅 역량은 v1에서 관측만 쌓는다.
- **역량마다 다른 형태를 동시에 적용.** 인지 부하를 늘린다. "1개로는 진도가 안 난다"가 데이터로 확인되면 올린다.
- **프로필 원본 교정 통로.** ⏸ 미결정(§10). 당장은 개입 사유 노출이 부분적으로 대신한다.

## 13. 알려진 리스크

1. **설치 단계 이탈.** Codex 훅 신뢰 승인이 조용히 실패한다. 자체 검증으로 막는다.
2. **숙련도 과소추정 편향.** 대화 밖에서 일어난 작업은 관측되지 않으므로([ADR 0001](adr/0001-누가-썼는지는-추적하지-않는다.md)),
   조용히 잘하는 학생일수록 관측이 적게 쌓이고 시스템은 그를 초보로 본다. 개입을 과하게 걸게 되고,
   아는 것을 계속 묻게 되며, **그 학생이 가장 먼저 도구를 끈다.** 랜덤 오차가 아니라 항상 낮게
   추정하는 계통 오차라는 점이 위험하다. 완화책은 설계 안에 있지만(우회 3연속 자동 침묵 전환,
   개입 사유 노출로 학생이 "그거 할 줄 아는데요"라고 말할 수 있게 하는 것) 근본 해결은 아니다.
3. **개입이 이탈 원인을 오염시킨다.** v1에 개입을 넣으므로, 이탈 데이터에 "설치 실패"와 "개입이 거슬림" 두 원인이 섞인다.
4. **emergent 태그 파편화.** 세 장치로 막지만 완벽하지 않다. 검색이 태그 전용이 아니라 텍스트 매칭도 하므로 치명적이지는 않다.
5. **추출 품질.** LLM이 관측을 잘못 뽑거나 놓친다. `src` 역참조로 사후 감사할 수 있고, raw가 남아 있어 재정제가 가능하다.
6. **`prompt.text` 보관.** 원문에 코드 조각이 섞일 수 있다. 7일 후 폐기로 완화한다.
